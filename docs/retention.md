# Confidential event data lifecycle

Set `EVENT_ENDS_AT` to the organizer-approved full ISO timestamp with an explicit timezone, for example `2026-12-01T18:00:00+08:00` (example only, not the event's date). No date is inferred. An absent date leaves automatic expiry unconfigured; an invalid nonempty date blocks access instead of silently extending retention.

Set a random `CRON_SECRET` in the hosting environment. `vercel.json` schedules authenticated cleanup daily at 16:00 UTC / 00:00 Beijing. The application closes submission, private editing, public views, photos, AI, TTS and admin data routes at `EVENT_ENDS_AT`, even if cleanup is delayed. Hosting cron timing and errors mean physical deletion must be verified; it is not a guaranteed exact-time erase. `/privacy`, admin login and retention diagnostics remain available.

An authenticated administrator can:

- `GET /api/admin/retention` to inspect state and whether the cron secret is configured.
- `POST /api/admin/retention` with `{"dryRun":true}` to count stored files without changing them.
- After expiry, POST `{"dryRun":false,"confirmEndsAt":"<endsAt from GET, normalized UTC>"}` to irreversibly delete event data. This endpoint cannot delete before the configured end time.

Both cleanup paths remove all app-owned private record versions, private archives, tombstones, slug markers, legacy public manuscript copies, photos, cartoons, loop videos and narration audio, including orphaned and previously soft-deleted data. A post-delete inventory must return `remaining:0`; errors or timeouts are incomplete and can be retried. Unrelated storage namespaces are excluded. Ordinary per-student Delete remains a reversible hide during the active event; whole-event cleanup is physical removal.

Legacy public manuscripts and all historical public media must also be privatized before the event. `POST /api/admin/storage-privatize` defaults to dry-run. The explicit body `{"dryRun":false,"confirm":"MOVE_LEGACY_TO_PRIVATE"}` archives each legacy JSON source in the private store and verifies the exact bytes, ensures usable current records and stable slug mappings, then removes that public JSON. A single legacy `data/people.json` is removed only after every entry is parsed and its private record/mapping is verified. A newer private edit is never overwritten. Failed private writes or mismatched archive readback retain the public source and return an error. All public photos, cartoons, loops and audio (including obsolete versions, deleted students and orphaned files) are copied byte-for-byte into private archives before any public media is removed. Historical record references receive owner-scoped private aliases. URLs are normalized to authenticated application proxies on read, without rewriting Person records or overwriting concurrent edits. `remainingPublicMedia:0` must be verified. Public slug markers contain IDs only, and are removed by event cleanup.

No routine request logs manuscript content. App responses use `no-store` and `no-referrer`. New media uploads use the private records store under `private-media/`, immutable content hashes, verified byte readback and `/api/photo/` proxies. The proxy checks the owner’s publication/preview/admin access; historical narration audio requires administrator access even for published people. No public storage URL is returned. Whole-event cleanup includes private media and all archives. Public media origins from before migration are removed only after verified private copying; old CDN/browser copies may outlive origin removal. Provider copies, exported/downloaded files, local operator backups or preexisting source-repository data are outside these drivers. The organizer must separately verify provider retention/deletion terms and remove any manually retained copies. Do not promise that a privacy page or application deletion erases such copies.

For deployment maintenance without an admin session, `/api/cron/privacy` requires the same `Authorization: Bearer <CRON_SECRET>` credential and a configured active event. GET is always dry-run regardless of query parameters; POST defaults to dry-run and requires `{"dryRun":false,"confirm":"MOVE_LEGACY_TO_PRIVATE"}` to execute. It is deliberately not scheduled. After event end it refuses privatization so archives cannot be recreated following purge. Never log or include the credential in artifacts.
